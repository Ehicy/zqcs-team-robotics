## 四轮输出与停止

**2026-10-16 实现：**新增 STM32 `lower-motor` 目标，使用现有 MG370 胶轮车的 TB6612 接线；不链接上层 TT/DRV8833/PS2 后端。旧 STM32 `board-link` 目标继续保持 STBY/PWM 低电平。

| 轮号 | 位置 | PWM | IN1 / IN2 | 编码器 A / B |
|---|---|---|---|---|
| M1 | 右前 | PB6 / TIM4 CH1 | PB0 / PB1 | PA0 / PA1，TIM2 ×4 |
| M2 | 左前 | PB7 / TIM4 CH2 | PB3 / PB4 | PA6 / PA7，TIM3 ×4 |
| M3 | 右后 | PB8 / TIM4 CH3 | PB5 / PB12 | PA8 / PA9，TIM1 ×4 |
| M4 | 左后 | PB9 / TIM4 CH4 | PB13 / PB14 | PB10 / PB11，EXTI ×2 |

当前轮位以 2026-10-17 明确车头后的逐轮 +15%、2 秒复验为准；上方早期试转记录中的轮位称呼已经被本表替代。M1/M3 正 PWM 向前，M2/M4 正 PWM 向后；电机与编码器按同编号配对。详见 [方向校准记录](08-speed-remote.md)。

两块 TB6612 的 STBY 共接 PB15。固件释放 PB3/PB4 的 JTAG 功能，保留 PA13/PA14 的 SWD。UART 仍是 ESP32 GPIO4 TX→STM32 PA3 RX，GPIO6 RX←PA2 TX，共地、115200、8N1。

PWM 载波为 20kHz，占空比请求单位为有符号千分比，当前上限 **±250‰（25%）**。开环 USB 请求的正负只表示电机端子驱动极性；闭环另用逐轮 `motor_sign` 和 `encoder_sign` 对齐车轮正方向，尚待实测。开环非零目标采用 1000‰/s 斜坡；闭环速度斜坡默认 500mm/s²。反向时先减到零，至少保持 50ms，再向反方向增加，不能通过先停止再反向绕过该等待。

零目标、STOP、命令失效和故障会撤去驱动。单轮为零且其他轮仍运行时，用 IN1=IN2=0、PWM=高实现高阻滑行；全停时拉低 STBY。**滑行不是机械瞬停**，停车距离、换向效果与负载仍须实测；导航所需的接近减速尚未实现。TB6612 的高阻/短刹车状态依据 [东芝数据手册](https://toshiba.semicon-storage.com/info/docget.jsp?did=10660&prodName=TB6612FNG)，不能简单把所有 PWM 置零称为滑行。

## 有效期、停止优先与故障关断

**2026-10-16 开环阶段：**`PWM` 使用独立消息类型 8，类型 3 `CONTROL` 保留毫米/秒含义，不把速度值作为占空比使用。

**2026-10-16 闭环阶段：**`CONTROL` 已接入 `lower-motor` 的四轮 PI，只有全部轮子校准确认、反馈有效、无锁存故障且请求有效时才放行。手机输入上限 300mm/s，PWM 输出仍限制为 25%；速度请求和开环 PWM 模式相互切换会撤销当前运动会话。STM32 `board-link` 仍不驱动电机。

每次新输入最多有效 200ms，ESP32 发送剩余有效期；STM32 再扣除串口缓冲停留时间。轮询、普通状态、编码器或灯控消息不能为旧输入续期。停止有优先级屏障：ESP32 锁存停止并重复发送禁用 PWM，STM32 撤销会话令牌；旧队列里的 PWM 无法恢复输出。新握手也会撤销旧控制，同一 ESP32 启动周期内快速重连不保留原运动会话。

USB 台架 PWM 文本必须带当前会话 token，防止停止/重连前的文本在稍后被当作新命令。token 是会话标识，不是身份认证或无线安全机制。

`lower-motor` 有独立的 1kHz SysTick。主循环未在 50ms 内完成并喂狗时，中断直接拉低 STBY 并锁存；主循环恢复后撤销旧会话，但保留锁存，需停车后显式清故障才允许重新解锁。持续故障上报故障码 6，通信和灯控仍可使用；普通 STOP 不清除该锁存。IWDG 使用独立 LSI 时钟作为后备，先启动再配置并核对读回；名义约 200ms，实际时间随 LSI 变化，本轮只验证停止喂狗能复位，未标定超时。初始化失败不能通过清故障绕过。异常处理也先关闭 STBY，不在异常中喂狗。

**STBY 网必须有外部下拉，建议 10kΩ 到 GND，并确认模块没有硬拉高。** MCU 复位期间 GPIO 为高阻，不能靠固件覆盖这一阶段。首次动力测试沿用 [完整供电与接线说明](lower-car-wiring.md)，逐轮架空、轻载进行；25% 占空比并不是电流限制，闭环的 500ms 无计数进展检测也不能替代电流保护。

## 四轮原始编码器计数

**2026-10-16 实现：**前三轮使用定时器编码器模式，第四轮使用 A 相双边沿 EXTI、读取 B 相确定方向。循环读取计数并延伸为可回绕的 32 位原始计数，停车和手动转轮期间也继续采样，约每 100ms 回传一次。

`ENC mask=15` 只表示四路采样后端运行并有新样本，**不证明传感器接好、不证明电机在转，也不是校准通过**。采样失效或反馈超过 200ms 会失去有效位。EXTI 无法保证恢复中断拥塞期间漏掉的所有边沿，高速计数仍须实测。

用户新商品图明确霍尔编码器标注 13PPR、供电范围 3.3–5V、输出上拉到 VCC，因此四个编码器的 VCC 接 STM32 3V3，GND 共地；不接 5V 或 12V。六针插头的物理线序、正转与 A/B 极性仍需逐轮实测，不能凭颜色推定。

用户给出的减速比为 34:1，轮径图示 65mm。**若 13PPR 指电机轴一圈的单相完整周期**，M1–M3 初值为 `13×34×4=1768`，M4 为 `13×34×2=884` 计数/轮圈。源码采用这些初值，但 `confirmed=0`；需要实际手转轮圈确认口径，并分别记录电机方向、编码器方向与有效轮径，不能将商品参数当成已经完成校准。

## 四轮 PI 与校准门禁

**2026-10-16 实现：**`firmware/shared/speed_control.c` 每 10ms 根据实际间隔和各轮原始计数差计算 mm/s，执行整数 PI、积分限幅、速度斜坡和换向等待。默认 `kp_milli=1000`、`ki_milli=2000`（Kp=1、Ki=2）、速度上限 300mm/s、加速度 500mm/s²；这些是待调初值，不代表整车控制效果。

闭环锁存反馈无效/异常、方向持续不符、控制周期异常，以及驱动期间 500ms 无计数进展。故障后撤去输出，显式清故障需要禁用输出且有效反馈显示近零速度；解锁不会自动恢复旧命令。无计数进展既可能是负载阻碍，也可能是编码器断线，不能仅凭该标志断言电机堵转。

逐轮机械参数与 PI 设置通过 BLE 面板送 UART 并等待 STM32 ACK；配置只在停止时接受，四轮全部确认后才允许手机 ARM。STM32 参数只保存在 RAM，复位恢复未确认；网页 localStorage 仅保留表单，不自动发送或解锁。界面、协议与步骤见 [速度闭环与手机遥控](08-speed-remote.md)、[网页说明](../firmware/web/README.md)。位姿里程计、直行/转角动作、导航和舵机执行尚未实现。

## 构建与 USB 台架入口

在仓库根目录执行；这些命令只构建，不烧录：

```text
python sample-mecanum-car-study/build_firmware.py --target lower-motor --toolchain "<Arm GNU bin目录>"
pio run -d firmware/esp32 -e board-link
```

STM32 产物在 `sample-mecanum-car-study/build/lower-motor/`；ESP32 工程环境名仍为 `board-link`，当前包含 USB 台架命令和 BLE 输入。选择 STM32 `--target board-link` 得到的是禁用电机的通信目标，不能只改 `LINK_ACTUATION_ENABLED` 来启用驱动。

USB 控制台（115200）可使用：

| 命令 | 含义 |
|---|---|
| `INFO` | 查看连接、当前 token、flags、错误计数 |
| `ENC` | 查看四轮原始计数、有效掩码和样本年龄 |
| `PWM <8位十六进制token> <M1> <M2> <M3> <M4>` | 当前会话的新占空比输入，四值均在 -250 至 250；单次最多 200ms |
| `STOP` | 立即撤销输入，优先请求停机并撤销会话 |
| `LED ON` / `LED OFF` | 保留 PC13 灯控诊断 |

STATUS 的 bit3=支持 PWM，bit4=支持速度闭环，bit2=STBY 禁用。能力位不代表校准通过；还须查看四轮 ready mask 与 fault。`QUEUED` 只代表请求排队，STBY 状态也不是转动或停车的光学/机械反馈。

需要连续短时测试时，先完成新固件的写入与实物接线检查，再**手动运行**有界单轮脚本（需要 pyserial）：

```text
python firmware/tools/motor_bench.py --port <ESP32实际串口> --expected-firmware crtc-lower-speed-ble-v1 --wheel 1 --pwm 150 --seconds 2
```

脚本固定本次会话，每 50ms 发新输入，默认最多运行 5 秒；明确添加 `--extended` 时最多 10 秒。遇到失联、token 改变、错误或状态超时立即退出，不自动重连续跑，结束和 Ctrl+C 均尝试 STOP。测试 M2–M4 时分别更改 `--wheel`；正负极性要靠实际观察确认。不要把本文命令示例当作已经执行过的动作。

`--wheel 1`、`--pair 1 2`、`--triple 1 2 3` 与 `--all-wheels` 必须四选一，分别指定单轮、两轮、三轮、四轮相同占空比的架空测试。两轮/三轮选项不接受重复轮号；工具不会自动选择、清故障或重试。各模式使用相同的会话、超时、限时和 STOP 检查，不代表电源能力已经验证。首次四轮测试的编码器故障及后续成功窗口均保留在上文，继续测试前须取得当前稳定的连接与无故障反馈。

`--expected-firmware` 必须与已核对的 `INFO firmware=` 完全一致；默认仍兼容旧 `crtc-lower-motor-console-v1`。当前源码标识为 `crtc-lower-speed-ble-v1`，2026-10-17 实板 ESP32 保留的固件标识为 `crtc-lower-pid-v2`，两者不能视为同一构建。脚本接受新增的速度能力位，但仍要求 PWM 能力、稳定的新会话和禁用输出状态；指定版本名不会跳过这些检查，也不会改写固件。

## 后续验收与开源使用说明

先在驱动禁用时手转四轮核对计数；再逐轮短时验证极性、停止和反转，验证断线、停止后旧命令、主控复位和循环异常的关断行为。记录供电、电流、温升、计数与实际转动对应关系。随后显式确认四轮参数，低速调试已实现的 PI，验证手机松手、断连、故障锁存与重连不续跑；里程计和路径代码实现后，再进行四目标方案中的 60cm 直行、90° 转向和两点往返测试。

本轮驱动与协议扩展在仓库内实现，沿用 ST CMSIS/标准外设库及 Espressif Arduino 框架，未引入外部导航库。定时器、复用和看门狗实现参考 [STM32F103 RM0008](https://www.st.com/resource/en/reference_manual/rm0008-stm32f103xx-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)；依赖与许可证见 [第三方清单](05-open-source.md)。
