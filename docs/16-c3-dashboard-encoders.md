## 接线

接线图：`firmware/web/esp32c3-wiring.html`，提供完整排针、独立串口图和逐根端点表。
默认 C3 正面朝人、USB/RST在上、天线朝下；STM32 USB朝上。

| 功能 | C3 | 底盘 STM32 |
|---|---|---|
| C3发送 → STM32接收 | IO18，右排第12针 | PB11，右排第5针 |
| STM32发送 → C3接收 | IO19，右排第11针 | PB10，右排第6针 |
| UART参数 | UART1，115200 / 8N1 | USART3，115200 / 8N1 |

GPIO号优先认丝印；排针序号仅适用于上述朝向。两板地线按图分别落在降压器 OUT−。
COM9 已确认经典 USB 转串口款，原生 USB 的 GPIO18/19在当前固件中让给 UART1。

| 轮位 | 编码器 A | 编码器 B | 计数方式 |
|---|---|---|---|
| M1右前 | PB4，左排12 | PB5，左排13 | TIM3 部分重映射，4倍频 |
| M2左前 | PB6，左排14 | PB7，左排15 | TIM4，4倍频 |
| M3右后 | PB0，右排8 | PB1，右排7 | EXTI0，仅A相双边沿，2倍频 |
| M4左后 | PB8，左排16 | PB9，左排17 | EXTI8，仅A相双边沿，2倍频 |

四路编码器 VCC 沿用历史 3.3V 接法，分别落在底盘右排第3针3V3；各编码器 GND 落在右排第1针 GND。
用户确认13PPR霍尔，实际编码器额定供电尚待核对；A/B必须为3.3V兼容信号，PB0/PB1不可直接接5V输出。
六线插头的孔序沿用旧资料，识别电源、A/B时仍以实际线束定义为准。

电机 PWM 保留 PA0/PA1/PA2/PA3，方向保留 PA4/5、PA6/7、PA8/9、PA10/15；PB15 为共用 STBY。
SWD 保留 PA13/PA14。TIM2不再用作编码器，避免与PWM冲突。

## Dashboard直接控制

打开 `http://127.0.0.1:8080/dashboard.html?v=c3-pwm3`，连接蓝牙设备 `CRTC-Lower-Car`；已授权设备可直接重连。
默认“直接 PWM”：按住方向直接输出，滑块为0–100%占空比，初值20%。不需要ARM、PID初始化、校准确认或清故障；电机/底盘反馈异常不联停其他电机。每轮独立显示实测速度，异常样本丢弃且不参与控制；PWM模式没有目标速度，目标栏显示“—”。
可选“PID速度控制”保留原速度环与参数流程；普通行驶的PWM和PID往复测试不共用物理单位。切换方式会停止当前动作。PID首次方向输入仍自动应用表单并取得控制回执。
连接本身不启动车辆；STOP、断连、会话变化、页面失焦和指令过期撤销当前动作，迟到回执不恢复运动。
机械参数标记表示选用的配置已应用，不代表已实测；每圈计数与方向仍应按实际编码器核对。

三张卡已分为独立布局：1统一PID、2四轮机械参数、3往复测试，手机端单列。
根因是三张卡此前都使用同一个CSS `grid-area: calibration`，导致重叠；此修复不改变PID算法。

## 反馈与PID

STM32每10ms按实际间隔采样轮速，四轮有各自的积分、D滤波和输出历史，共用一组从C3下发的Kp/Ki/Kd。
仅回传原始计数、实测/目标轮速及状态，不回传PID内部积分历史。
M1/M2和M3/M4倍率不同。13PPR为单相周期、34:1减速比的旧假设对应1768/1768/884/884计数/轮；Dashboard已使用独立缓存键，避免复用旧三硬件计数方案的M3参数。
每轮手转输出轴一整圈所得差值才是本车的实测CPR。

软件采样有效标志不等于识别到了编码器插头；静止的有效计数0不能证明线路接好。
中断计数保留20μs脉宽资格判断，每路每毫秒最多32次中断；中断过密只暂停该路采样至下一窗口后自动重试，不关闭手动PWM，也不需要清故障。独立测速对不合理跳变丢弃该轮样本，其他轮继续显示。

### 继电器与每根电源线

沿用此前无线继电器NC/COM/NO/+V/−V模块，认实物丝印，不按图片左右猜。
电池正极→总保险/总开关输入；总开关输出分别到继电器COM及+V；
继电器NO分别到升压IN+、降压IN+；NC不接；−V单独回电池负极。
升压IN−、降压IN−各自回电池负极。升压OUT+12V给驱动VM；OUT−给驱动GND。
降压OUT+5V分支给C3、STM32及三舵机；舵机电源和回线不经过开发板。
每根设备负极在V8表里有确定的降压OUT−或升压OUT−落点，没有悬空“公共GND”标签。
非隔离变换器内部IN−/OUT−导通需按实际模块核对。
NO同时控制两路转换器，因此继电器断开时主控5V也断，Dashboard会失联；它不是软件电机停止命令。

### 位置库与机械臂状态

1. 先用舵机滑块调好目标，在动作工坊选舵机，点“读取该路滑块目标”。
2. 输入名称，点“保存/覆盖同名位置”。保存的是目标PWM指令及所属通道，不是测得的轴角。
3. 三路组合状态可直接填各路角度，或“读取三路滑块目标”；命名保存后“一键到此状态”。
4. 选择已存位置/状态可“载入编辑”再保存同名覆盖；可删除；名字支持中文。
5. 本浏览器持久化；换电脑、清缓存前使用“导出全部记录JSON”，另一浏览器可导入。
   导入只读入记录，不执行任何动作。配套保存键为`crtc-motion-library-270-v1`，不与旧360°记录混用。

### 动作积木

“由此状态生成积木”生成三路顺序动作；“位置→加入积木”复用单路命名位置。
每块可调整舵机、目标、前置积木、触发条件、延时及到位稳定等待。

- 前置选“任务开始”：并行启动，可各自加延时。
- 选前置积木+“PWM到位后”：当前PWM回读到目标且轨迹moving位清零，再等待所填稳定时间。
- 选“启动后”：从前一积木开始计时，到指定秒数启动下一块。
- 选“经过指定角度后”：根据前一舵机的PWM回读穿过阈值触发，可再加延时。

例如：积木1大臂到160°；积木2小臂到95°，依赖1“启动后0.5秒”；
积木3开门，依赖2“PWM到位后0.3秒”。并行动作会在BLE队列依次发送，并不是同一微秒输出。
同一路重叠动作会报告配置冲突，而不是悄悄互相覆盖。命名保存后可载入再次调整。
**三线舵机没有实际到位反馈**；“PWM到位”及稳定时间不能替代限位开关、轴角传感器或堵转检测。

### 示教录制与相对轨迹复刻

1. 保持蓝牙与串口在线，核对机械参数表CPR、编码器方向、轮径和等效轮距。
2. 点“开始录制”，用WASD/触控手动开车，同时使用舵机滑块或已存机械臂动作。
3. 点“结束录制”，输入路径名并“保存本次记录”。包括四轮原始计数、左右轮相对累计里程、
   手动输入/速度比例、时间及舵机目标；编码器逐侧缺测质量也一起保存。
4. 车在任何地点开始都可以，但初始朝向和机构姿态应与原录制起点一致。选择路径，点“复刻”。
5. 回放采用录制前馈+相对左右轮程误差修正；不是只按原时间盲放WASD，也不要求地图坐标。
   可调回放速度比例、里程误差Kp和终点容差。机械臂目标触发时，底盘先归零等待，机械臂结束后继续。
6. 用户STOP、手动方向接管、页面离开、连接或会话改变会结束当前自动任务，不自动续跑。
   主控只接受短期命令，自动程序目前由前台浏览器调度，并非整条轨迹上传到MCU离线执行。

坏数据自动剔除，不需另选编码器开/关模式。单路坏可用同侧另一轮；左右各坏一路仍可估计。
同侧两路全坏则该段位姿不可观测，继续录制的驱动前馈并标“估计/位置未验证”。
恢复时重新对齐每侧参考锚点，只追踪恢复后的增量，避免将缺口路程补走第二遍。
只有新编码器包到达才更新定位，不能用旧计数配新渲染时间反复计算速度。
编码器断流记录为缺测，不把缓存里程当成真实停止。改变机械参数应重录，不强行套用旧轨迹。

### 算法来源与没有做到的事

当前真实底盘是四胶轮差速：M1/M3右，M2/M4左。采用同侧冗余、逐轮速度/加速度门限、
置信度渐变、精确SE(2)增量积分和缺测恢复重基准；没有套麦轮矩阵。
参考[WPILib差速运动学](https://docs.wpilib.org/en/stable/docs/software/kinematics-and-odometry/differential-drive-kinematics.html)、
[Road Runner里程计](https://rr.brott.dev/docs/v0-5/tour/kinematics/)，动作图参考
[Road Runner Actions](https://rr.brott.dev/docs/v1-0/actions/)。异常拒绝思路可参考
[robot_localization EKF实现](https://github.com/cra-ros-pkg/robot_localization/blob/rolling-devel/src/ekf.cpp)，
本实现是透明的门限/冗余融合，不冒称完整移植EKF或FTC Java库。

同侧两路同样“合理”却分歧时，两票无法证明谁坏；代码保留低置信估计。全零也可能是真的不动、
电机堵住或编码器断线。四轮共同打滑不一定能由轮编码器识别；轨迹复刻是轮轴里程复刻，不保证地面轨迹完全一致。
加陀螺仪可独立约束角速度，在理想差速条件下配合剩下一侧估算另一侧，但也不能观察整车共同平移滑移。

值得进一步研究的论文（目前不声称已在本车验证）：

- Han, 2009, *From PID to Active Disturbance Rejection Control*,
  [DOI 10.1109/TIE.2008.2011621](https://doi.org/10.1109/TIE.2008.2011621)：ADRC/ESO把负载、摩擦与模型偏差合为总扰动估计；
  对低成本MCU有吸引力，但观测器仍需可信输出，不能凭空补齐整侧传感器缺测。
- Chen et al., 2016, *Disturbance-Observer-Based Control and Related Methods—An Overview*,
  [DOI 10.1109/TIE.2015.2478397](https://doi.org/10.1109/TIE.2015.2478397)：DOB可在现有控制器旁补扰动估计，
  相比立刻更换整套控制器更易逐步试验；依赖电机模型、滤波与噪声权衡。
- Ayyıldız, 2023, *Adaptive sliding mode based fault tolerant control of wheeled mobile robots*,
  [DOI 10.1080/00051144.2023.2190866](https://doi.org/10.1080/00051144.2023.2190866)：自适应滑模处理机器人不确定性/故障；
  需要核对其故障与可测状态假设，不能直接宣称适用于任意两路编码器断线。实际PWM与量化下还要控制抖振。

当前优先顺序是把前馈+逐轮可信反馈调好，再用实测数据评估LADRC/ESO，而不是未经参数辨识就换成“神奇算法”。


### STM32逐轮自动融合PID与M3方向修正

新STM32标记`0xC3D71023`。日常百分比输入和历史mm/s输入最终共用同一个PA自动反馈路径；
非PA历史构建的原PID代码保留。四轮各自维护积分与D历史，系数仍由C3统一下发。
每10ms以已斜坡/换向的PWM作前馈；模型速度=逻辑PWM比例×满PWM参考轮速。
新界面已将机械表的`max_mm_s`标为“满PWM参考轮速/历史速度上限”，默认300mm/s仅是初值。
未收到PID系数时仍可前馈行驶；收到系数即使用可信反馈，无需四轮confirmed确认，也不伪造确认标志。

- 本轮可信：本轮反馈优先。
- 本轮失效：优先同侧另一轮；直行时可混入另一侧两轮低权重参考，同侧权重为单个对侧的6倍。
- 同侧都失效：只有四路逻辑PWM同向且差不超过2‰舍入容差时才借另一侧；质量较低。
- 转弯或原地旋转：不跨侧借轮速；同侧全失效则保持前馈，不关其他轮。
- 全部反馈不可信：保留前馈，编码器持续采样，恢复自动渐入；替代轮速只用于控制，不当作真实编码器里程。

缺测、异常跳变、无脉冲、反向和过大加速度只降低相应轮可信度，不抛出整车锁存故障。
代用反馈不积累失效轮积分，旧积分泄放，D状态重置。反馈修正最大±250‰，不限制总PWM的0–100%；
修正渐入最多每10ms变化10‰，失去所有可信观测时立即撤修正回前馈，所以不是保证最终PWM任何变化都≤10‰。
不能凭控制算法区分所有真实堵转与编码器断线；替代反馈也不能反映失效轮自己的负载。

用户实测右后电机反向，因此只反转M3的默认电机极性：M1/M2/M3/M4为`+ / − / − / −`。
编码器方向保持原值。C3默认、STM32前馈归一化、Dashboard PA配置一致；旧浏览器v1缓存迁移时只反转M3一次，
保留其他轮、轮径、CPR、编码器方向与PID值，重复刷新不再次反转。
现机不重烧可先刷新Dashboard，停车后点“写入四轮配置”应用方向；这仅写RAM，旧固件掉电会恢复旧默认。
新版C3烧录后默认M3已修正；新版STM32还包含上述自动融合控制。接线端子不因软件反相而调换。

## 2026-10-23 快起快停修正（v4，待烧录）

用户确认当前是常规四胶轮差速底盘；轮序仍为M1右前、M2左前、M3右后、M4左后。同侧前后轮同逻辑指令，A/D为转向。本次不改电机或编码器方向，后轮方向由用户自行调整。

旧版虽有Kp=1、Ki=2、Kd=0数值，但PA分支的`pid_initialized`可能在会话变化时被清掉，使日常驱动只剩前馈；STOP仅STBY拉低滑行。本次PA分支上电就启用上述PID预置，保留每轮独立历史与置信反馈融合。普通STOP、串口重握手不抹掉系数；C3空闲时重试系数同步，仍可从Dashboard调整。这些是可用初值，不是实车调优结果；物理标定confirmed仍为0，不伪造已标定。

启动改为200ms五次S曲线，满驱动仍允许100%。松键/空格/STOP发送独立的一次性`LINK_QUICK_STOP`帧（类型14，载荷为剩余制动窗口），优先发送，不等周期心跳。STM32先撤驱动10ms，再最多30ms制动：可信本轮测速且仍同向时反推不超过5%占空比，且不大于本轮刚才的驱动幅值；接近零速则停止反推，用短路制动收尾；检测到反向立即结束。无可信本轮测速时使用TB6612短路制动，不借用邻轮速度反推。短路制动为STBY高、该轮IN1/IN2均高且PWM高，其余零轮保持滑行。刹车输出绕过PID，避免补偿放大刹车脉冲。反向请求也先执行同样的短促制动，再按新方向重新曲线起步。

窗口按首次收到的停止事件计时，重复STOP不续期；过期窗口跳过，不补播。串口故障、会话变化、指令超时及掉线直接撤驱动，并取消制动；没有自动恢复旧方向输入。40ms是软件制动窗口，不是保证整车40ms内停稳或刹车距离，也不等于限流；实车效果仍需架空/低速验证。

固件：`output/quickstart-20261023/stm32/dashboard-motor.hex`（ST-Link、0x08000000、标记`0xC3D81023`），C3为`output/quickstart-20261023/esp32/`，INFO名称`crtc-c3-quickstop-v4`。两板需配套更新；新STM32能力位0x20与旧C3不兼容，避免只烧一块就测试。舵机IO7/6/10、上电不回中不变。Dashboard `dashboard.html?v=quick-v4`通过双板能力回传显示是否已安装该版，未识别时明确提示旧版只撤驱动。

后轮方向若只写入旧固件RAM，重烧后要在Dashboard停车写入已保存的四轮配置。本轮没有替用户再次反转轮向，没有自动执行车辆或舵机运动。
