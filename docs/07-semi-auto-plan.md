# 下层车四目标半自动导航方案

更新：2026-10-17。**本文记录已确定的半自动功能方案，导航尚未实现或完成实车验收。** 四轮编码器采样、轮速 PI 和 BLE 手动遥控已实现；电脑网页直行及左右转短测已有用户观察与停车反馈，M4 候选修复后的左右转短测无故障。连续里程计、定距离/定角度动作、任务协议和路网执行仍未实现，不能直接用当前手动面板测试四目标导航。当前实际进度以 [PROJECT.md](../PROJECT.md)、[速度闭环说明](08-speed-remote.md) 和 [功能验证记录](04-validation.md) 为准。

下层车采用四个 MG370 编码器电机、胶轮、两块 TB6612、STM32F103C8 和 ESP32-S3-N16R8。上层车继续负责推落方块，下层车完成收集与接收。本方案只规定下层车的路径与操控关系，不从旧模型推定最新底盘或夹爪尺寸。

## 红蓝方选择与四类目标停靠

**2026-10-16 方案确定：**开机由操作者选择红方或蓝方，加载对应路线，再选择四类目标之一。控制界面应显示所选阵营、目标和当前停靠状态，避免把另一侧场地的目标直接用于本车。

| 按键 | 目标 | 停靠用途 | 需要落实的场地数据 |
|---|---|---|---|
| 1 | 洞穴黄块 | 行驶到洞穴黄块前的安全停靠点 | 红蓝方各自的停靠位置、朝向和机构操作空间 |
| 2 | d1 / e8 侧目标 | 行驶到相应场地标号附近的作业停靠点 | 红蓝方与 d1、e8 的对应关系，实际停靠位置和朝向 |
| 3 | h1 / a8 侧目标 | 行驶到相应场地标号附近的作业停靠点 | 红蓝方与 h1、a8 的对应关系，实际停靠位置和朝向 |
| 4 | 桥下 | 行驶到桥下接块位置，配合上层车推落 | 可通行范围、等待姿态、接块位置及退出路线 |

`d1`、`e8`、`h1`、`a8` 是用户给出的场地标识，不能直接当作已标定的毫米坐标。红蓝方转换和停靠朝向需要与实际场地核对；没有测量依据时不生成坐标、车宽、转弯半径或距离阈值。四个目标是可选择的目的地，不预设成必须按固定顺序执行的四段录像式动作。

路径到达与收集动作分开记录。车辆停到目标附近，不等于黄块或普通方块已经收集，也不等于上层车已经完成推落；夹爪、翻臂和接块动作的型号、行程、时序及成功判据仍需依据机械资料实现与验收。

## 根据当前位置在路网中选择路径

**2026-10-16 方案确定：**用小路网连接起点、绕障碍拐点和四类停靠点，只记录允许通行的连接关系。第一版仅在停车待命时接受新目标，根据当前已确认的节点选路，例如“洞口停靠点→通道拐点→桥下停靠点”；不要求固定按 1、2、3、4 顺序访问，也不为每一种顺序单写一套动作。自动执行中不直接换目标或重新选路，需要先取消、停稳并确认位置。

路网节点记录可停车与转向的位置，路段记录已测的通行方向、长度、速度限制和允许车体姿态。具体路网和选路算法属于后续实现内容；在场地尺寸和车体包络尚未核实前，不把抽象路线写成可下发执行的坐标表。

“动态选路”表示依据已知路网、有效位置和操作者确认的信息选路。当前方案没有已实现的环境感知：不能自动发现对方机器人、掉落方块或临时障碍，也不能把里程计当作避障传感器。操作者发现障碍、路径受阻或实际位置明显偏离时必须接管；停稳并确认位置与可行路段后，才能重新规划并开始新任务。

## 停车转向、直线行驶与接近减速

**2026-10-16 方案确定：**每段按“停车→转向→直行→减速停车”执行，转向结束先停稳再直行。第一版不做边走边转的曲线。

执行中持续检查距离、方向、命令有效期与反馈状态；达到目标前按已验证的减速规则降低速度，到达后保持停车。具体速度、加减速度、位置误差与角度误差阈值均待测量和台架、场地测试确定，不从旧 TT 麦轮车直接复制到当前 MG370 胶轮车。

车体通行空间必须包含底盘、料仓、翻臂和夹爪在实际姿态下的外廓。转向时检查整个车体与夹爪扫掠空间，不能只检查车体中心轨迹。机构展开、夹持方块或负载变化后，需要重新核对转向和停靠条件；是否要求先收拢机构，由机械实测与后续控制约束明确。

## 人工接管、停靠对齐与恢复运行

**2026-10-16 方案确定：**流程为“手动/待命→自动导航→到站停车→人工微调”。自动行驶中拨动手柄或按停止键，立即取消任务、清空待执行动作与旧控制队列，进入手动；旧任务随后到达的串口消息或重复手机消息不得使车辆恢复自动行驶。停车撤去驱动与车体真正停止分别判断，不能用通信停止指令代替实际停稳。

第一版在夹取或人工微调结束后，要求操作者手动退回附近已标定的停靠点，**实际对齐停靠位置与朝向后，按“确认位置”**，再选择下一目标；不需要回到最初起点。仅点击按钮、不实际对齐，不能作为坐标复位依据。待实际测试证明里程计足够稳定后，再考虑从手动调整后的估计位置直接接入路网；第一版不启用这一方式。

手机失联、双板通信失联、控制有效期耗尽、动作超时，或持续驱动却没有编码器进展的疑似堵转，均应停车报错并撤销任务。当前速度环已有驱动期间 500ms 无计数进展检测，不等同于电流保护或已验证的地面堵转保护；动作超时与任务撤销尚待实现。重连后保持停车，由操作者重新确认状态和位置并启动；不能因为链路恢复就继续旧路线，也不能由 ESP32 给缓存旧命令续期。

## STM32 与 ESP32 的职责

**2026-10-16 方案确定：**任务规划放在 ESP32，底盘反馈与动作执行放在 STM32；以下是待实现的完整分工，不表示这些功能已经完成。

| STM32F103 | ESP32-S3 |
|---|---|
| 读取四轮编码器，计算轮速 | 读取四目标按键、手动控制与停止指令 |
| 四轮速度闭环及加减速限制 | 保存红蓝方地图、停靠点和允许路段 |
| 连续估计位置与朝向，手动期间也更新 | 根据已确认节点选路，逐段下发任务 |
| 执行直行一段、转向一个角度及停车 | 显示当前目标、动作进度与故障 |
| 检查通信超时、动作超时与疑似堵转 | 接管、取消及重连时清理任务，禁止自动续跑 |

## 编码器轮速闭环与持续里程计

**2026-10-16 方案确定：**STM32 先实现真实编码器采样、计数方向和速度换算，再用四轮轮速闭环跟踪请求。里程计持续利用有效编码器增量估算位移和朝向，覆盖自动行驶与人工接管期间，不在每个短动作开始时随意清零；重置定位必须有明确的初始化或人工停靠对齐确认。

编码器计数代表轮轴转动，不能直接证明车体在地面发生了对应位移。四胶轮底盘原地转向会发生侧向擦滑；加减速、地面条件、负载及个别轮打滑也会造成里程计误差。左右等效轮距和距离换算需实测标定，纯编码器里程计的角度与位置误差会累积，不能宣称绝对定位或长期无漂移。人工停靠对齐用于纠正已积累误差；是否增加其他定位传感器留作后续设计，不写成已装配事实。

首先重复测试 **原地转 90°** 和 **直行 60cm**：每次记录目标、里程计估计值、实际测量值、转向方向、速度、负载和地面条件，比较平均误差及多次结果的离散程度。分别检查左右转和往返直行，并观察串联多段后的累积偏差。通过范围由实测数据、停靠空间及比赛需求确定，当前不编造次数、容差或已经合格的结果。

## 任务身份、序号校验与结果回传

**2026-10-16 方案确定：**半自动任务需要独立任务 ID，并将执行状态、控制消息序号和结果对应到同一任务。消息处理检查版本、长度、会话、任务 ID、序号、有效期和校验结果；拒绝重复、乱序、损坏或属于旧任务的数据，不能用这些消息刷新当前控制有效期。

沿用现有 UART 分帧、CRC、会话和超时能力作为基础；动作消息至少包含任务号、序号、动作及参数、校验，STM32 回报执行中/完成/失败与里程计。新增任务层尚待实现，当前开环 `PWM` 消息不具备这些导航含义。控制面板应区分请求已接收、任务正在执行、目标已到达、用户取消、超时或故障，不能把“发送成功”或通信 ACK 当作真实到达。取消与重连后收到的旧成功结果不得覆盖新任务状态。

队列规则与命令有效期需要跨手机、ESP32 和 STM32 一致：队列等待消耗原有有效期，接管、取消或换会话清理旧任务。通信恢复、普通状态上报和编码器回传均不授予继续旧任务的权限。

## 分层开发与逐项验收

**开发顺序（2026-10-17 更新）：**电机、编码器、速度环与 BLE 已有实现和短测基础，下一层是里程计与基本动作；本节的导航验收项均尚未完成。

| 层次 | 开发内容 | 验收记录应包含 |
|---|---|---|
| 电机驱动 | 四路 TB6612 输出、方向、限幅、停止和通信失效撤销 | 四轮对应与正反转、零输出与停机、实测供电及实际负载条件 |
| 编码器与轮速闭环 | 四轮有效采样、极性/计数换算、测速和闭环 | 手动转轮与实际计数对应、目标与实测速率、反馈失效处理 |
| 里程计与基本动作 | 连续位姿估计、停车转向、直线和减速 | 90° 转向、60cm 直行重复测量、负载与地面变化、累积误差 |
| 两点低速往返 | 先连接两个已标定的安全点，验证选路与分段执行 | 两方向低速往返的到站范围、停车可靠性与重复误差 |
| 路网与四目标 | 红蓝方场地数据、停靠姿态、已知路网选路与扫掠空间检查 | 从不同有效起点前往各目标，检查到达位置、朝向和机构干涉 |
| 接管与任务生命周期 | 手动接管、取消、人工对齐确认、新任务启动 | 旧队列被清空、重复与旧任务拒绝、失联停止、重连后不续跑 |
| 手机与双板联调 | 手机目标选择/状态显示、ESP32 任务管理、STM32 执行反馈 | 匹配任务 ID 与序号的状态及结果、端到端停止和失联测试 |

最后完整验证“自动到站→手动微调夹取→退回附近停靠点并对齐确认→下一目标”，再测试断联和中途接管。第一版验收目标是重复到达可人工接管的安全区域、可靠停车并能继续前往下一目标，不是自动精准夹住方块。

每一层分别记录源码实现、主机测试、两端构建、烧录读回和实车测量；上一层通过不等于整条导航链路通过。没有环境感知时，场地联调始终由操作者观察并负责及时接管。最新模型、停靠坐标、车体与夹爪扫掠尺寸，以及各项实际验收结果补齐后，再将对应条目标为完成。

## 半自动首测准备（2026-10-17）

最新补充：用户实测前后轮中心距 130mm、左右轮中心距 165mm、整车 240×190mm、轮径 65mm，确认落地且测试空间足够。电脑地图已采用用户提供的 V1.5 场地截图原图：内框 2400×2400mm、300mm 格，红方 a1 / 蓝方 h8 格中心为假定起点，默认红方、初始车头朝场内。比赛坐标映射与往返预览已实现；这不是实物场地检测，动作执行固件仍待实现。地图及原遥控 46 项逻辑测试通过，未执行自动导航实车轮次。摄像头方面仅识别到手机文件传输连接，尚未取得手机实时视频。

后续用户确认车已落地，并要求实时地图。电脑网页已加入展示用编码器轨迹：停车设相对起点，按四轮各自 CPR/轮径/极性累计路程，有轮距后显示二维估计与车头方向；轮距未填则不生成位置。坐标 X 沿初始车头，Y 向初始左侧，左转为正。断联、会话改变、500ms 采样间断、参数修改或明显计数跳变后冻结；需人工重新设起点。地图 10 项加原遥控 33 项主机测试通过，页面加载检查通过，未做地面运动验收。此网页估计不替代计划中的 STM32 持续里程计，现有 BLE 回传缺少源时间戳及启动编号，不能用于自动动作控制。

本轮集中测量清单：前排/后排各自左右轮胎宽度中线间距、左侧/右侧各自前后轮轴中心距、实际轮径、行驶姿态整车最大长宽（含伸出机构）；另记录前方及两侧可用空间、地面材质。轮距和空间优先，目标场地坐标可后补。用户已落地不等于已确认有 1m 安全直线空间。

本轮只完成准备与现状核对，未下发自动运动指令。网页只读检查显示 BLE/UART 在线、四轮配置 4/4、四轮目标和实测速均为零、控制已锁定。实时状态不能替代下次启动前的检查。

已有参数可复用：M1 右前、M2 左前、M3 右后、M4 左后；电机方向 `[+1,-1,+1,-1]`，编码器方向 `[-1,+1,-1,+1]`，粗测 CPR `[1756,1791,1774,898]`，标称轮径 65mm。前三路计数为 4×、第四路为 2×，不能统一套用同一 CPR。轮胎受载有效直径、地面打滑与转向误差仍需测量。

实现按以下顺序推进，不能跳过底层直接加入四目标按钮：

1. STM32 连续累计四轮位移，得到左右平均路程；再以经过标定的等效轮距估计朝向和位置，手动期间持续更新。轮距未知时不输出可信的转角或二维定位。
2. STM32 增加单动作执行器：直行距离、原地转角、减速、停稳确认，以及运行中/完成/取消/失败状态。距离由编码器反馈决定，定时器仅作超时保护，不能用“速度乘时间”代替测距。保留现有速度环故障、硬件看门狗及输出限幅。
3. 双板和 BLE 扩展动作消息及能力声明，校验会话、任务号、序号、参数范围和原始有效期；旧固件或未确认参数拒绝自动启动。人工方向输入、STOP、断联、复位或配置改变撤销任务，迟到消息和重连不能续跑；启动 ACK 与实际停稳完成分别上报。
4. 桌面网页加入单次动作测试与进度/失败原因，默认锁定，不在连接、刷新或写配置后自动执行。先完成主机仿真、协议回归、两端构建和烧录读回，再进行架空动作与中断验证。
5. 落地单段通过后才加入 ESP32 路网与两点往返；四目标坐标、朝向和车体扫掠空间由实测数据提供。
