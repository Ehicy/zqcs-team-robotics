## 下层车双板通信与供电

从 [下层车功能开发历程](02-lower-car.md) 阅读：由旧方案转为 STM32＋ESP32，10-13 完成 UART 和灯控验证，10-15 整理 12V/5V 供电，10-16 核对机械装配与后续安排。具体接线及协议见 [整车接线与通信说明](lower-car-wiring.md)。

下层车为四个 MG370、胶轮、两块 TB6612、STM32F103C8 和 ESP32-S3-N16R8。历史 `board-link` 基线禁用电机且有灯控证据；当前已使用 `lower-motor` 完成电脑 BLE 电机短测，二者验收记录分开。

## 下层车电机、手机遥控与四目标半自动方案

[电机与编码器说明](06-lower-motor.md) 记录独立 `lower-motor` 后端、四轮原始编码器采样及 ESP32 USB 台架命令；[速度闭环与手机遥控](08-speed-remote.md) 记录四轮 PI、ESP32 BLE 与 [Android 静态面板](../firmware/web/README.md)。当前开环 PWM 上限 25%、闭环上限 50%，网页速度上限 300mm/s，重启后逐轮校准仍需明确写入确认。电脑 BLE 直行、转向和停止已有实板短测；Android 实连、长期带载与精确速度跟踪待验收。

[四目标半自动方案](07-semi-auto-plan.md) 规定红蓝方选择、小路网选路、停车转向与直行、人工末端调整及对齐确认。网页已显示编码器估计轨迹和比赛底图，STM32 导航动作及路网执行尚未实现，位置精度待实测。DS3128 大臂 GPIO12、MG995 小臂 GPIO13 的微调已烧录；DS3128 转回有用户确认，MG995 回执通过、目视待确认，完整行程和带载能力待验收。

## 功能验证与中期材料准备

[验证与证据索引](04-validation.md) 分别标出源码、构建、写入读回、队员观察和待验证项目；小体积原始通信记录放在 [evidence/](evidence/)。原始 Flash 和完整本地备份不进入仓库。

参赛正文均在根目录 `docs/`，按具体功能使用 H2 标题，功能内按有证据的日期从早到晚组织。根目录 README 是入口，PROJECT 是工程维护记忆，源码目录的说明保留工程导航用途。

清理前的原始项目记录保留在 [PROJECT.before.md](../PROJECT.before.md)，仅供查看历史讨论与方案迭代；其中过时接线、进度和已清理的本地备份路径不代表当前状态。

提交前还需团队完成以下事项，当前上传不等于已经邮件提交中期材料：

- 最新机械模型已归档至 [模型目录](../output/mechanics/team-solidworks-20261017/README.md)，仍需补充实测外廓、重量、机构运动、成本/借用件清单及对应证据。
- 对照 V1.5 第 9 页逐项确认拟申报功能；已有电机和电脑 BLE 短测，但精确闭环、长期带载及导航仍需验收，不将源码或主机仿真记为实际行驶完成。
- 确认中期底盘指标对手机 BLE 替代 PS2 的认定；目前上层仍使用 PS2，下层电脑 BLE 已实测，Android 实连待验收。
- 拍摄需要的视频：MP4、至少 1080p/30fps，按手册第 11 页打包并提交；此前 720×1280 的行驶视频不满足该视频规格。
- 提交默认分支的仓库链接；规则测评、邮件正文及视频附件由团队另行完成。
