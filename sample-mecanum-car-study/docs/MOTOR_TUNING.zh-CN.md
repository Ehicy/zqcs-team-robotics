## 方案来源与适配

- [Pololu Simple Motor Controller G2：Motor settings](https://www.pololu.com/docs/0J77/5.2)：开环 PWM 控制的加减速限制、起转阈值和换向等待。
- [ArminJo/PWMMotorControl](https://github.com/ArminJo/PWMMotorControl)：有刷电机的 PWM 斜坡、起转参数与单轮补偿；该项目采用 GPL-3.0，当前嵌入式工程也附带 GPL-3.0 许可证。
- [TI：Sensorless brushed DC control using ripple counting](https://www.ti.com/lit/an/slvafo8a/slvafo8a.pdf)：无编码器闭环仍需要电气信号采样，文中的 DRV8214/DRV8234 功能不属于当前 DRV8833。

本工程根据公开方法编写 C 控制层，未引入 Arduino 依赖或第三方源文件。公开方案的“速度”量在这里表示驱动占空比，不是实际 RPM。参数是调试起点，未按本批 TT 马达和车重实测标定。

## 默认参数与行为

配置入口为 `hardware/Inc/motor_tuning.h`。

| 参数 | 默认值 | 含义 |
|---|---|---|
| `MOTOR_ACCEL_PERCENT_PER_SECOND` | 200 | 满幅目标下，PWM 约 0.5s 从 0 增到 100% |
| `MOTOR_DECEL_PERCENT_PER_SECOND` | 1000 | 目标降低或换向时的 PWM 下降速率 |
| `MOTOR_REVERSAL_COAST_MS` | 40 | 需要反转的轮子降到零后，至少保持零输出的时间 |
| `MOTOR_UPDATE_MAX_MS` | 20 | 单次斜坡最多推进的时间；循环卡顿后不突跳到全速 |
| 每轮前进/后退增益 | 100/100 | 分别校正机械前进、后退方向；仅允许压低，范围 0–100 |
| 每轮前进/后退最低 PWM | 0/0 | 0 表示关闭；实测起转阈值后再配置，范围 0–100 |

任一轮要求反向时，四轮统一降到零，再等待需要反转的轮子满足 40ms 零输出间隔，随后朝最新摇杆目标缓升。过程中不用阻塞延时，手柄仍持续读取。松杆后再快速反推也遵守间隔。等待时间不能证明转子已停下。

斜坡使用 DWT CPU 周期计数得到的实际毫秒时间，不假设每次手柄轮询恰好 10ms，也不占用 TIM2/TIM3/TIM4 或延时所用 SysTick。仅主循环读取时钟；72MHz 下至少每约 59s 读取一次以捕捉周期计数回绕，当前每轮约十几毫秒读取。

`motor_set_speed_percent()` 保留为输出上限接口，当前默认上限 100，并非“上电以 100% 运行”。降低上限立即限制输出；设为 0 立即停车。普通调速由摇杆完成。

## 怎样校准四个轮子

1. 在实际使用的电池电压、载荷和轮组上测试；每轮区分前进与后退方向。四轮顺序为左后、右后、左前、右前。
2. 先保留最低 PWM 为 0。用相同 PWM 比较各轮，压低明显偏快轮子的对应增益，例如将 100 改为 95 后重新比较。无编码器时可用轮子标记和录像比较相同时间的转数，不能保证以后所有负载下仍一致。
3. 从低 PWM 增加，记录每轮从静止能可靠起转的最低占空比，填入最低 PWM。零轮始终保持零；补偿不能超过当前输出上限。它会改变非零轮之间的比例，因此启用后必须重测横移、斜移和旋转。
4. 起步过猛时降低加速率；換向仍有明显冲击时增加零输出等待。无需为调参改手柄解析或接线。

每行参数依次为 `前进增益, 后退增益, 前进最低PWM, 后退最低PWM`。后轮负的电气输出对应机械前进，控制层已处理，校准参数按机械方向填写。

## 电流、电压能否估计转速和负载

可以建立估计器，但当前接线没有电流/电压 ADC 采样，本版没有伪造反馈或实现闭环估计。

在有刷电机近似稳态下，反电动势 `E ≈ V_motor − I_motor × R`，转速 `ω ≈ E / Ke`，电磁转矩 `T ≈ Kt × I_motor`。模型还受电刷压降、温升引起的电阻变化、摩擦及减速箱效率影响；动态时需考虑电感项。电机端有效电压受 PWM、续流状态和驱动压降影响，不能直接用电池电压代替。[TI 对有刷电机反电动势的说明](https://e2e.ti.com/support/motor-drivers-group/motor-drivers/f/motor-drivers-forum/1536063/drv8262-drv8262evm-drv8262-reverse-emf-and-protection-for-brushed-dc-motor-application)

估计单个轮子的转速/负载，需要相应的电机电流与端电压采样，并校准 R、Ke、Kt。只测整车总电流适合做电流异常提示，不能分别解出四轮的转速与转矩；总电流还是 PWM 电源侧电流，不等于每轮绕组电流。DRV8833 的芯片采样/限流端不等于小板已提供可读的转速或电流数据，不能把 NC 当 ADC 信号。

另一条无编码器路线是采集有刷换向产生的电流纹波并计数。它需要电流前端、ADC/比较器和滤波，不是把现有 PWM 数值送进 PID 就能实现。STM32 ADC 输入也需要正确的分压/放大和保护，不能直接接 8.4V 或 H 桥电机端。

### 用户实机反馈：前后正常，横移伴随转弯（2026-10-02）

用户确认前后行驶没有问题。左杆纯左移时车身向左平移并沿圆弧转弯，车尾靠圆心；纯右移时转弯方向相反，仍是车尾靠圆心，区别于右杆控制的旋转。横移尚未验收通过。

源码核对：右杆在死区内、左杆仅有横向输入时，当前O形混合没有主动叠加旋转量；两组对角轮的目标绝对值相同，默认四轮增益100、最低PWM0，共同比例斜坡不会在从静止起步时单独改变某轮的比例。按已记录的极性，纯左移预期机械方向为左前/右后前进，右前/左后后退；纯右移全部反向。这是代码的预期输出，不是对实际轮速/地面作用力的测量。

用户进一步架空确认：纯左移时上述四轮机械转向全部符合，而且四轮都在转。实际最上方滚子轴线是否与O形记录一致仍待确认；尚未测量各轮实际转速、接地载荷和滚子阻力，不能由PWM相同推断实际RPM相同。用户要求先推测写好：据此试验性降低前轴横移分量至85%，并增加人工辅助训练和 Flash 保存；新试验版已烧录并读回一致，实车效果仍待验证，详见 [横移学习与保存](DRIVER_CALIBRATION.zh-CN.md)。
