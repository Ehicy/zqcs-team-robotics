## 已修复或澄清

| 发现 | 影响 | 本版处理 |
|---|---|---|
| PWM 原公式为 duty * ARR - 1 | 零输入得到 -1，随后浮点转 uint16_t 超出可表示范围；可能产生错误输出 | 先限制输入，再计算 duty * PWM_PERIOD_COUNTS；零输入直接返回 0，1 对应完整周期计数数 |
| 四轮混合最大可到 1.4 | 超出 0～1 的 PWM 预期，逐轮硬截断又会改变比例 | 找到四轮最大绝对值；仅超过 1 时四轮同时除以它，PWM 层再作兜底限幅 |
| 摇杆没有中心死区 | 回中偏差会造成输出 | 中心 128、死区 ±8，死区内归零，区外连续映射到 ±1，端点两侧分别计算分母 |
| 模式错误时不更新电机 | 旧的比较寄存器和方向继续有效 | ps2_read 返回有效标志，失败立即调用 motor_stop，不处理按键 |
| 原始包没有固定标志检查 | 错位/异常数据容易被当成命令 | 检查模式 0x73 和固定字节 0x5A；失败清空按键、摇杆回中 |
| 原按键逻辑先于模式检查执行 | 通信异常可能伪造一次松开事件 | 只对有效帧处理按键，异常时清除所有历史按键状态 |
| 上电/恢复后推杆状态会直接生效 | 操作者可能未准备好，车即开始驱动 | 等待控制用的三个摇杆轴回中且全部按键松开，下一轮才接受运动 |
| motor_init 没有独立开启 GPIOA 时钟 | 暗中依赖 pwm_init 的调用顺序 | motor_init 自己开时钟，方向脚预置低；启动 PWM 时初始 CCR 为零 |
| 原先先更新 PWM、再改变方向 | 新幅度可能短暂与旧方向组合；反转直接带旧输出 | 保留 L298N 接口，更新方向前先将 EN 的 PWM 清零，随后写方向和新 PWM；未实现动态反转缓冲 |
| PWM 频率注释错误 | 容易把 50 Hz 误认为 20 kHz | 更正注释。正常 TIM3 时钟 72 MHz、PSC=71、ARR=19999，实际 50 Hz；按“电机暂不改”保留数值 |
| PS2 通信循环依赖 8 位移位溢出退出 | 对新手不直观 | 改为 bit 从 0 到 7 的固定 8 次循环，仍低位先传 |
| PS2 初始化只预设 CS | CMD/CLK 初始化电平不明确 | 在切换 GPIO 输出前将 CMD、CS、CLK 预设高；选中及字节之间留短延时 |
| ps2.h 写 PA4～PA7，但源码使用 PB12～PB15 | 按注释接线会接错 | 统一注释；按钮改用标准 SELECT/L3/R3/圆/叉等名称，实际兼容手柄丝印需核对 |
| 函数指针数组 16 项全部是 temp | 阅读困难且没有真实按键动作 | 改为单次循环 + on_button_released 中的 switch；保留“松开时触发”语义，记录 last_released_button 供调试 |
| 头文件彼此包含 main.h | 依赖关系绕、无关代码互相牵连 | 模块头只声明自己的接口，源文件按需包含库；sys.h 保留兼容但主控制代码已不使用位带宏 |
| pwm_set5/6/7 有声明无实现，MOTOR_NO_PID 宏没被使用 | 容易误以为有额外舵机通道或可切换 PID | 移除这些误导性声明/宏，未凭空补功能 |
| delay_us 用固定 9 倍计数且未处理 0 | 暗中依赖 72 MHz；0 延时存在计数异常风险 | 初始化时读取 SystemCoreClock，用 HCLK 计数，LOAD=ticks-1，零延时直接返回；长毫秒延时分成 1 ms |
| Keil 的时钟元数据为 12 MHz，源码假设 HSE=8 MHz | 工程信息与源码不一致 | 工程元数据对齐 8 MHz，同时删除不存在的 include 路径；真实晶振仍需实物确认 |
| 上游留有历史 Listings/map | 容易误当作本版构建结果 | 交付压缩包排除这些旧构建记录和个人 IDE 状态文件 |

关于 PWM 零值的严谨表述：C 语言中，-1.0 浮点数直接转换成 uint16_t 超出范围，属于未定义行为；不能保证在所有编译器上都恰好变成 65535。可以确认的是：该公式错误，不能用作零输出。

## 为初学者保留的阅读结构

1. main.c：主循环、有效帧判断、回中条件、按键 switch。
2. ps2.c：GPIO 初始化、固定 8 位通信、9 字节包的拆解。
3. motor.c：死区映射、四轮组合、整体缩放、L298N 输出。
4. pwm.c：定时器配置、占空比到 CCR 的换算。

没有引入 RTOS、回调框架或多层驱动抽象。新手可以先把一个函数当作整体使用，再逐层展开。

## 还没有解决的实物问题

### 无线失联识别并不完整

现在能检测的是 STM32 读到的模式/标志不符合要求。数据包没有本程序可使用的校验和、无线链路心跳或序号；某些接收器在手柄关机后可能继续返回格式正确的旧数据，这种情况本版无法识别。

因此不能把“错误包停车”称为“任何无线失联都能停车”。后续必须实际测试关手柄、断开接收器 DATA、拔接收器供电和距离失联。不得仅以“连续数据不变”作为失联依据，因为持续推杆本来也可能产生相同数据。代码位置：main.c 的 TODO_LINK_LOSS。

### 模式与通信兼容性

ps2_init 只设置 GPIO，不发送完整的模拟模式配置序列。先尝试手柄上的 MODE/ANALOG 切换，以实际 mode 值 0x73 为准，不用指示灯颜色判断。0x41 和 0x79 均拒绝。所加的固定微秒延时不是 ACK 握手；兼容接收器的时序、电平和供电仍须看卖家资料与实测。

### 电机与机械方面

保留旧 L298N 引脚和原四轮正负号，未确认 1～4 对应实车哪个轮子。50 Hz 只是继承原工程，不代表适合你们的 TT 电机。没有编码器反馈、轮速闭环、起步/反转斜坡，也没有最大电流控制。motor_stop 撤掉驱动，车可能因惯性继续滑行。DRV8833 适配步骤见下节。

### 主循环卡死与硬件异常

当前故障异常处理函数停在死循环，硬件 PWM 可能继续运行；本版没有加独立看门狗或硬件停机线。此事需要与整车电控设计一起完成。原系统时钟启动也存在等待 PLL 的循环。main.c 的 TODO_WATCHDOG 是后续入口；仅靠读取函数返回值不能处理这些情况。

SysTick 当前被阻塞延时独占，不能同时用作 RTOS 或周期中断时基；也不能在中断中重入 delay_us。未来增加耗时夹爪动作应采用逐次推进的状态逻辑，避免长时间 delay 导致遥控无法更新。

| motor.c / motor_stop | 明确新驱动的滑行和制动状态 |

本次对 motor.c 的修改是算法修复、命名和旧接口的输出顺序整理，没有将电机驱动换成 DRV8833。与电控 A 对接时应先约定轮子编号、接线和符号。
