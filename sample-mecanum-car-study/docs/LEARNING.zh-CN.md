# 电控 B 阅读指引

先读 README.md，再按照 main.c → ps2.c → motor.c → pwm.c 阅读。原理不需要一次全部学完。

## 第一遍：main.c

从文件底部的 main 开始：
1. delay_init 准备延时，motor_init 内部调用 pwm_init，让 TIM2/TIM3 的八个输入从零占空比开始。
2. ps2_init 配置手柄通信引脚。
3. while (1) 每次调用 control_step，再等待 10 ms。
4. control_step 首先读一帧，返回无效就停止输出并清除按键历史。
5. 刚上电或刚从异常恢复时，必须松开按键、让左摇杆上下/左右和右摇杆左右回中，才能重新允许控制。
6. 正常后调用 buttons_process，然后调用 motor，把三个原始摇杆值交出去。

重要变量：
- ps2Data：这一轮手柄数据。
- control_ready：是否已经完成回中，可以接受运动指令。
- button_was_down：上轮各按键是否按下。
- last_released_button：最后一个松开的按键编号，255 表示尚无事件。

按钮保持原来的“松开时触发”，不在按住期间重复。先认识 switch，再把自己需要的非阻塞动作加到 on_button_released。叉键/圆键目前只是预留注释，没有夹爪程序。

## 第二遍：ps2.c

ps2_comm 的 8 次循环就是发送一个字节、同时接收一个字节。先看 bit=0，然后 bit=1，直到 bit=7，观察 bit_mask 如何选中当前位。

ps2_read 总共交换 9 个字节，然后检查模式和固定标志；有效时把后面的字节放入结构体。返回值是“1 有效 / 0 无效”；这是相对上游的接口变化。

在 Keil Watch 中观察 ps2Data 四个轴和两组按钮。工程没有 printf/串口发送功能，因此不能只加 printf 就默认电脑能看到数据。

## 第三遍：motor.c

motor 参数依次是：左摇杆上下、左摇杆左右、右摇杆左右，仍用 0～255 原始值。

示例（保持原项目的编号和方向约定）：

| 调用 | 四轮带符号输出比例 |
|---|---|
| motor(128,128,128) | 0, 0, 0, 0 |
| motor(0,128,128) | +0.5, +0.5, +0.5, +0.5 |
| motor(128,0,128) | +0.5, -0.5, -0.5, +0.5 |
| motor(128,128,0) | -0.4, -0.4, +0.4, +0.4 |
| motor(0,0,0) | +3/7, -2/7, +2/7, +1 |

120～136 的摇杆数值视为回中。输出是开环驱动比例，并不是每分钟转数；不要用输出变量冒充实际测速反馈。

“同时平移和旋转”时可能超过 1，四轮一起除以最大绝对值才可以保留比例。先用上表算一遍，再展开 pwm_set 调用。

最后的 pwm_set1～4 接收带符号输出，每个电机占用相邻两个 PWM 通道。正向为 PWM/0，反向为 0/PWM，零值为 0/0 滑行。换向先清旧方向再给新方向，不是机械减速斜坡。

## 第四遍：pwm.c

周期共有 PWM_PERIOD_COUNTS 个计数，计数器从 0 数到 PWM_PERIOD_COUNTS-1。PWM1 中计数器小于 CCR 时输出高电平：
- CCR=0：0%。
- CCR=1800：50%。
- CCR=3600：100%。

注意只有 ARR/PSC 寄存器参数按计数规则减 1；占空比计算不再减 1。

正常 72 MHz 定时器时钟下，PSC=0、ARR=3599，对应 20 kHz；这是初始调试参数，实测低速和温升后再调整。TIM4 留给舵机。

## 没有板子时的练习

电脑有 Python 3 与 GCC 时，在项目根目录执行：

```sh
python3 tests/run_tests.py
```

测试使用项目真实的 C 计算和控制代码，但把电信号与定时器操作模拟出来。读 tests 不是前置任务；先学懂 hardware 下四个文件即可。

拿到板子后，需要在 Keil 里完整编译，并先验证手柄数据和输出波形，再由电控 A 完成单轮架空测试。与接收器有关的失联、模式和电平限制见 REVIEW.zh-CN.md。
