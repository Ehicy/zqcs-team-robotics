# 横移人工辅助学习与 Flash 保存（2026-10-02）

这是未完成实车验收的试验版。左杆控制相对车头的平移方向与 PWM 幅度，右杆左右控制旋转；上电实际输出 0，模拟模式 `0x73`、松开按键且摇杆回中后使能。L1/R1 不调速，上限 100%。

加速率从 200 改为 500 个百分点/秒：满幅目标下约 0.2 秒从 0 到 100%；减速率 1000 个百分点/秒；反向前的零输出等待从 80ms 改为 40ms。松杆、START、数字/无效帧立即撤驱动。这些参数用于改善用户反馈的“黏糊”，尚未实测电流、换向冲击和响应。

## 补偿解决什么问题

用户确认前后行驶正常；纯横移一边平移一边沿圆弧转弯，车尾靠圆心，左右移的转弯方向相反。架空纯左移时四轮方向均符合 O 形混合：左前/右后机械前进，右前/左后机械后退。

据此试验性减小前轴横移分量：前轴 85%、后轴 100%。这是对前后横向作用不均的推测，未测量轮速和地面作用力，也没有排除滚子安装、载荷或阻力差异。参数仅缩放混合中的横移项，纯前后和纯右杆旋转不受影响；斜移和横移加旋转受影响，仍须重测。

```text
左后 = F - rear × L + T
右后 = F + rear × L - T
左前 = F + front × L + T
右前 = F - front × L - T
```

随后共同归一化、应用单轮校准和后轮电气反向补偿。保存过的参数优先于编译默认值。前、后轴参数各限于 50～100%，表示横移分量增益，不是整个轮子的速度上限。

## 边开边训练

1. 先正常驾驶观察横移；普通驾驶不会学习。
2. **按住 SELECT，只向左或向右横移**，左杆上下保持回中。右杆用小幅旋转抵消偏航，凭车身实际方向判断纠偏；持续保持约 0.6 秒后开始学习。
3. 右杆纠偏逐渐不需要时，让右杆回中。算法依据纠偏方向缓慢调整前/后轴横移增益；单次按住 SELECT 最多改变 10 个百分点。需要继续训练时松开 SELECT，再重新按住。
4. 松开所有按键和控制轴，停车回中至少 2 秒；参数有变化时自动保存。两次保存尝试至少间隔 30 秒，间隔未满会延后。保存成功或参数已相同，PC13 快闪两下。

学习要求归一化横移幅度至少 30%，右杆纠偏幅度不超过横移的 35%；前后/斜向行驶、大幅右杆旋转、停机或 SELECT 与其他键组合时不学习。右杆原有转向控制仍生效，算法没有能力区分操作者有意转弯与纠偏，所以训练须明确按住 SELECT。

这是根据 O 形混合推导的试验学习律：操作者是反馈来源。没有陀螺仪或轮速测量，不能自行判断车是否走直；尚未证明实车收敛。若训练使偏航加重，松开 SELECT 停止学习，使用下面的恢复或手动调整。

## 手动调整和恢复

| 按键组合 | 动作 |
|---|---|
| SELECT + □ | 前轴横移增益减 5 个百分点 |
| SELECT + △ | 前轴横移增益加 5 个百分点 |
| SELECT + 方向键 ↓ / ↑ | 后轴横移增益减 / 加 5 个百分点 |
| SELECT + × | 恢复前后 100/100，取消横移补偿；停车回中后自动保存 |
| SELECT + ○ | 控制轴回中时请求保存；仍遵守 30 秒写入间隔 |
| START | 撤输出、清运动目标及按键状态，需松键回中恢复；**保留校准参数** |

组合键按下边沿只执行一次，长按不连续调；同轴加减键一起按时忽略。行驶中按保存组合会被忽略，需要回中后重新按。写 Flash 前八路 PWM 比较值全部清零，保存后也须松键回中再行驶。保存失败时快闪五下；失败尝试同样受 30 秒间隔限制。

行驶时 PC13 仍在任一轮实际 PWM 严格大于 60% 时闪烁；停车时的短促保存提示是另一种灯态。POWER 电源灯不受代码控制。

## 为什么不能只靠当前接线自动测转速

搜索到的无编码器有刷电机控制仍需电气测量：[NXP AN10513](https://www.nxp.com/docs/en/application-note/AN10513.pdf) 使用电流与反电动势 ADC；[Precision Microdrives AB-021](https://www.precisionmicrodrives.com/ab-021) 在 PWM 关断期间测反电动势；[基于 SVM 的换向纹波检测论文](https://arxiv.org/abs/2403.18833) 从测量的电流识别换向脉冲。当前两线 TT + DRV8833 的接线没有这些模拟采样，不能直接移植成轮速闭环。

[PWMMotorControl](https://github.com/ArminJo/PWMMotorControl) 提供开环 PWM 斜坡、起转阈值、单轮校准和参数保存的参考方法；本工程用 C 实现适用部分，没有复制 Arduino 源文件。当前人工辅助学习律由 O 形混合推导，并非该仓库已验证的现成算法。

ST-Link 能读取 `control_mode`、`ps2Data`、`target_duty`、`applied_duty` 和校准状态，观察软件是否按输入运行；没有物理反馈时仍无法从这些量得到实际 RPM、车身偏航或负载。

## Flash 和构建

STM32F103C8 按 64KiB Flash 使用：代码限于前 62KiB，最后两个 1KiB 页 `0x0800F800～0x0800FFFF` 保存参数。GNU 链接脚本和 Keil 工程均已缩小代码区，不依赖探测器报告的额外容量。

每条记录 16 字节，包含版本、序号、前后增益、反码、CRC16 和最后写入的提交标记。按槽追加，页面满后擦除另一页；新记录完成前保留旧有效记录。相同参数不重复写，默认值不会在每次开机自动写入。主机故障注入验证了半字写入/页擦除失败后的旧记录恢复，不等于已完成实板掉电试验。

CubeProgrammer 下载本版 HEX 并按其代码页擦除时不会覆盖参数页；选择 **Full chip erase / Mass erase 会清除参数**。开机找不到有效记录时回到前 85%、后 100% 编译默认值。

最新构建输出 `build/driver-calibration/crtc-driver-calibration.hex`，BIN 9820 字节，静态 RAM 176 字节；SHA256：

`e63d2d344055c2d1e3ef1119b3c49d9bdac6eb4b5283ced4ea662627bd730ab8`

9 个应用 C 文件真实 STM32 头文件检查、主机行为/Flash 故障测试和 Arm GNU 三目标构建通过。原有 `ps2-led` / `motor-buttons` 独立示例不包含本版学习功能。已用CubeProgrammer下载校验，并独立读回9820字节与BIN完全一致；启动读取模式73、使能1、前85/后100、72MHz和八路CCR全0。用户按SELECT+○后，实板参数页读到序号0、前85/后100的CRC有效记录；软件复位后loaded=1、dirty=0，参数一致、输出为0，验证了实际写入和复位恢复。此处保存的是试验默认值，不是已经训练出的实车校准。横移改善、训练收敛、电流温升和写入途中断电恢复仍待实测。

本轮 ST-Link 初始报无法获取核心 ID；用户确认 VM 已断电、重新插紧 SWD 后，以100kHz软件复位连接成功，NRST未接。64KiB备份识别了之前的7260字节开环版，主循环约12.68ms。用户说明整机电源接通后可配对，热连接读取确认模式73、回中127/128；此前手柄闪烁不能当作代码错误。用户随后仅断VM、保留主控和接收器供电，完成新试验版下载。详细证据见 [ST-Link 板上诊断](STLINK_RESEARCH_2026-10-02.zh-CN.md)；旧版历史见 [调优历史](MOTOR_TUNING.zh-CN.md)。

用户确认保存操作时看到了双闪，PC13 保存提示已目视验证。下一步先关电池电源、接回两块驱动板的VM线，再上电回中，落地比较横移和人工辅助学习效果。

源码入口：`calibration_control.c` 是训练和按键操作，`calibration_store.c` 是双页记录，`calibration_flash.c` 是 STM32 Flash 后端；`motor_tuning.h` 配置响应和默认参数。调试符号地址随构建变化，须使用对应 ELF，不能沿用旧固件地址。
